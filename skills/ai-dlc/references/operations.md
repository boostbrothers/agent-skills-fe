# Operations 페이즈 — 상세 가이드

Operations 페이즈는 Construction에서 구축된 시스템의 배포, 관측성, AI 기반 유지보수를 다룹니다.

## 1단계: Deployment Unit 패키징

AI가 시스템 배포에 필요한 운영 산출물을 생성합니다.

### AI가 생성하는 산출물

- **컨테이너 설정** — Dockerfile, 로컬 개발용 docker-compose
- **Infrastructure as Code** — Terraform, CDK, CloudFormation, 또는 Helm 차트
- **CI/CD 파이프라인 정의** — GitHub Actions, GitLab CI, 또는 동등한 도구
- **환경별 설정** — 개발, 스테이징, 프로덕션 별도 설정

### 산출물 형식

저장 위치: `aidlc-docs/plans/deployment_plan.md`

```markdown
# 배포 계획: {Unit/시스템 이름}

## 사전 조건
- [ ] {사전 조건 1: 예) AWS 계정 설정 완료}
- [ ] {사전 조건 2: 예) Docker 설치 완료}

## 인프라 구성요소
| 구성요소 | 서비스/도구 | 설정 |
|----------|-------------|------|
| {구성요소} | {예: AWS Lambda} | {주요 설정 상세} |

## 배포 단계
1. {구체적 명령어가 포함된 단계}
2. {구체적 명령어가 포함된 단계}

## 롤백 절차
1. {문제 발생 시 복원 방법}

## 환경 변수
| 변수명 | 설명 | 필수 여부 |
|--------|------|-----------|
| {VAR_NAME} | {용도} | 예/아니오 |
```

### 검증 계획

배포 전에 AI가 검증 계획을 생성합니다:

```markdown
## 배포 검증
- [ ] 인프라 프로비저닝 성공
- [ ] 애플리케이션 에러 없이 시작
- [ ] 헬스 체크 엔드포인트 응답 확인
- [ ] 스모크 테스트 통과
- [ ] 통합 지점 검증 완료
```

AI가 검증을 수행하고, 보고서를 생성하며, 식별된 이슈를 수정합니다.

## 2단계: 관측성 구성

AI가 시스템의 NFR과 SLA를 기반으로 모니터링 전략을 설계합니다.

### AI가 생성하는 산출물

저장 위치: `aidlc-docs/plans/observability_plan.md`

```markdown
# 관측성 계획

## 메트릭
| 메트릭 | 출처 | 알림 임계값 | SLA 목표 |
|--------|------|------------|----------|
| {예: API 지연시간 p99} | {예: CloudWatch} | {> 500ms} | {< 200ms} |

## 로깅 전략
- **로그 레벨:** {각 레벨에서 기록되는 내용}

- **보존 기간:** {로그 보관 기간}

## 트레이싱

## 대시보드
- {대시보드 1}: {표시 내용, 모니터링 담당자}

| {이름} | {트리거 조건} | 위험/경고 | {담당자, 대응 런북} |
```

## 3단계: AI 기반 모니터링

배포 후 AI가 지속적인 운영을 지원합니다:

### 이상 탐지
- 메트릭, 로그, 트레이스의 패턴 분석
- 지연시간 급증, 에러율 증가, 리소스 고갈 감지
- 잠재적 SLA 위반을 사전에 예측

### 인시던트 대응
- 증상과 잠재적 근본 원인의 상관관계 분석
- 사전 정의된 런북에서 대응 방안 제시:
  - 리소스 스케일링 (예: DynamoDB 처리량 증가)
  - 트래픽 관리 (예: API Gateway 재분산)
  - 장애 격리 (예: Circuit Breaker 활성화)
- 개발자가 완화 방안을 검증하고 승인

### 지속적 개선
- 텔레메트리 데이터에서 최적화 기회 식별
- 비용 최적화 제안 (적정 규모 조정, 예약 용량)
- 관찰된 패턴을 기반으로 아키텍처 개선 권장

## 개발자 검증

Operations 페이즈 전반에 걸쳐:
- 배포 설정을 실행 전에 승인
- 관측성이 모든 주요 경로를 포괄하는지 확인
- 자동화된 복구 조치를 리뷰하고 승인
- 조직의 SLA 및 리스크 프레임워크 준수 확인

## Operations 완료 기준

- [ ] 대상 환경에 시스템 배포 완료
- [ ] 헬스 체크 및 스모크 테스트 통과
- [ ] 관측성 (메트릭, 로그, 트레이스) 설정 완료
- [ ] 알림 규칙 설정 완료
- [ ] 배포 문서화 완료
- [ ] 롤백 절차 문서화 및 테스트 완료
