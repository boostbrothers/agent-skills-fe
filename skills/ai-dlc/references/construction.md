# Construction 페이즈 — 상세 가이드

Construction 페이즈는 Inception 페이즈의 Unit을 테스트 완료된 배포 가능 코드로 변환합니다. 작업은 Bolt — 시간 또는 일 단위의 빠른 반복 주기 — 를 통해 진행됩니다.

## Mob Construction 리추얼

팀이 물리적 또는 가상으로 함께 작업하며, 도메인 모델 단계에서 도출된 통합 명세를 교환하고, 함께 결정을 내리고, Bolt를 완성합니다. AI가 기술적 워크플로우를 주도하고 개발자가 각 산출물을 검증합니다.

## 1단계: Domain Design

인프라 관심사와 독립적으로 핵심 비즈니스 로직을 DDD 전술적 패턴을 사용하여 모델링합니다.

### AI가 생성하는 산출물

각 Unit에 대해 AI가 다음을 포함하는 도메인 모델을 생성합니다:

- **Entity** — 시간이 지나도 유지되는 식별자를 가진 객체
- **Value Object** — 속성으로 정의되는 불변 객체
- **Aggregate** — 불변 조건을 강제하는 루트 Entity를 가진 Entity/Value Object 클러스터
- **Domain Event** — 도메인에서 발생한 중요한 사건의 기록
- **Repository** — Aggregate 접근을 위한 추상화
- **Factory** — 복잡한 생성 로직의 캡슐화
- **Domain Service** — 특정 Entity에 자연스럽게 속하지 않는 오퍼레이션

### 산출물 형식

저장 위치: `aidlc-docs/design-artifacts/{unit-name}_domain_model.md`

```markdown
# 도메인 모델: {Unit 이름}

## Entity
### {EntityName}
- **식별자:** {식별 방법}
- **속성:** {주요 속성 나열}
- **행위:** {주요 메서드/오퍼레이션 나열}
- **불변 조건:** {이 Entity가 강제하는 비즈니스 규칙}

## Value Object
### {ValueObjectName}
- **속성:** {불변 속성}
- **검증:** {제약 조건}

## Aggregate
### {AggregateName} (루트: {RootEntityName})
- **포함 요소:** {Entity와 Value Object}
- **불변 조건:** {Aggregate 수준 비즈니스 규칙}
- **커맨드:** {이 Aggregate를 변경하는 오퍼레이션}
- **이벤트:** {발행하는 Domain Event}

## Domain Event
- `{EventName}` — {트리거 조건}일 때 발행

## Repository
- `{RepositoryName}` — {목적, 주요 쿼리}

## 컴포넌트 상호작용
{주요 유저 스토리를 충족하기 위해 컴포넌트가 어떻게 상호작용하는지 기술}
```

### 개발자 검증

도메인 모델을 제시하고 다음을 확인합니다:
- Aggregate 경계가 올바른가?
- 누락된 도메인 개념이 있는가?
- 불변 조건이 실제 비즈니스 규칙을 반영하는가?
- 엣지 케이스는 어떻게 처리해야 하는가? (예: 신규 고객의 누락된 데이터)

## 2단계: Logical Design

비기능 요구사항과 아키텍처 패턴을 적용하여 도메인 모델을 확장합니다.

### AI가 생성하는 산출물

- **아키텍처 패턴** 적용 (CQRS, Event Sourcing, Saga, Circuit Breaker 등)
- **기술 매핑** — 각 컴포넌트를 구현할 서비스/프레임워크
- **Architecture Decision Record (ADR)** — 트레이드오프가 포함된 주요 결정 문서화

### 산출물 형식

저장 위치: `aidlc-docs/design-artifacts/{unit-name}_logical_design.md`

```markdown
# 논리 설계: {Unit 이름}

## 아키텍처 개요
{아키텍처 접근 방식에 대한 상위 수준 설명}

## 패턴 결정

### ADR-{번호}: {제목}
- **상태:** 제안됨 / 승인됨 / 폐기됨
- **컨텍스트:** {이 결정이 필요한 이유}
- **검토한 옵션:**
  1. {옵션 A} — 장점: {장점}, 단점: {단점}
  2. {옵션 B} — 장점: {장점}, 단점: {단점}
- **결정:** {선택된 옵션}
- **근거:** {이 옵션이 요구사항에 가장 적합한 이유}
- **영향:** {시스템에 미치는 영향}

## 기술 매핑
| 컴포넌트 | 기술 | 근거 |
|----------|------|------|
| {컴포넌트} | {기술 선택} | {이유} |

## API 계약
{적용 가능한 경우 Unit 간 인터페이스 정의}

## 데이터 흐름
{시스템을 통해 데이터가 어떻게 이동하는지 기술}
```

### 개발자 검증

권장사항을 제시하고 다음을 확인합니다:
- 패턴 선택이 우리의 규모와 제약 조건에 적합한가?
- 이 선택을 덮어쓰는 조직 표준이 있는가?
- 트레이드오프가 수용 가능한가?

## 3단계: 코드 생성

Logical Design으로부터 실행 가능한 코드를 생성합니다.

### 원칙
- 클린 코드 실천: 작은 함수, 의미 있는 이름, 단일 책임
- 도메인 모델 컴포넌트를 합의된 기술 스택에 매핑
- 사용자와 합의한 프로젝트 폴더 구조로 코드 구성
- 클래스/모듈별 개별 파일 생성

### AI가 생성하는 산출물
- 모든 도메인 컴포넌트의 구현 코드
- 설정 파일
- 데이터베이스 스키마 또는 마이그레이션 파일 (해당되는 경우)

### Construction 계획

코드를 생성하기 전에 계획을 수립합니다:

저장 위치: `aidlc-docs/plans/{unit-name}_construction_plan.md`

```markdown
# Construction 계획: {Unit 이름}

## 단계
- [ ] Entity 클래스 생성
- [ ] Value Object 생성
- [ ] 불변 조건이 적용된 Aggregate Root 생성
- [ ] Repository 인터페이스 및 구현체 생성
- [ ] Domain Service 생성
- [ ] API 레이어 (컨트롤러/핸들러) 생성
- [ ] 설정 파일 생성
- [ ] 리뷰 및 승인
```

## 4단계: 테스트 생성 및 실행

AI가 포괄적인 테스트를 생성하고 실행합니다.

### 테스트 카테고리
1. **단위 테스트** — 개별 도메인 컴포넌트와 비즈니스 로직 테스트
2. **통합 테스트** — 컴포넌트 상호작용과 데이터 흐름 테스트
3. **기능 테스트** — 유저 스토리 인수 조건 검증
4. **보안 테스트** — 정적 분석, 의존성 스캐닝, 입력 검증
5. **성능 테스트** — NFR 검증을 위한 부하 테스트 시나리오

### AI의 수행 작업
1. 유저 스토리 인수 조건에 매핑된 테스트 케이스 생성
2. 테스트 스위트 실행
3. 실패 분석 — 실패 지점과 코드 변경사항의 상관관계 파악
4. 실패한 테스트에 대한 수정안 제시
5. 수정 후 전체 통과될 때까지 재실행

### 개발자 검증
- 커버리지 누락에 대한 테스트 시나리오 리뷰
- 테스트가 실제로 인수 조건을 검증하는지 확인
- 수정안 적용 전 승인

## 브라운필드: 코드 Elevation

기존 시스템의 경우, Domain Design 전에 elevation 단계를 삽입합니다:

### 정적 모델 Elevation
AI가 기존 코드베이스를 분석하여 다음을 생성합니다:
- 책임이 명시된 컴포넌트 목록
- 컴포넌트 간 의존성 그래프
- 데이터 모델 요약

### 동적 모델 Elevation
AI가 주요 유스케이스를 식별하고 컴포넌트 상호작용을 추적합니다:
- 핵심 흐름에 대한 시퀀스 다이어그램
- 통합 지점 및 데이터 계약

저장 위치: `aidlc-docs/design-artifacts/elevation_static_model.md` 및 `elevation_dynamic_model.md`

개발자가 이러한 모델을 검증한 후 표준 Construction 흐름을 진행합니다. 이를 통해 AI가 기존 시스템에 대한 정확한 컨텍스트를 확보합니다.

## Construction 완료 기준

Bolt는 다음이 모두 충족되면 완료됩니다:
- [ ] 도메인 모델 승인 완료
- [ ] Logical Design과 ADR 승인 완료
- [ ] 코드 생성 및 리뷰 완료
- [ ] 모든 테스트 통과 (기능, 보안, 성능)
- [ ] 코드 변경사항 커밋 완료
