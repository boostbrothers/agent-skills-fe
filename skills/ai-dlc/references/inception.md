# Inception 페이즈 — 상세 가이드

Inception 페이즈는 비즈니스 Intent를 실행 가능한 작업 항목으로 변환하는 단계입니다. 핵심 리추얼은 **Mob Elaboration**으로, AI가 분해를 주도하고 팀이 검증하는 협업 세션입니다.

## Mob Elaboration 리추얼

Mob Elaboration은 전통적으로 수 주가 걸리는 순차적 요구사항 작업을 수 시간의 집중 세션으로 압축합니다. AI가 제안하고, 팀(Product Owner, 개발자, QA, 이해관계자)이 검토하고 개선합니다.

### 1단계: Intent 포착 및 명확화

Intent를 문서화하는 것으로 시작합니다 — 상위 수준의 목적 선언문입니다.

**AI가 다음과 같은 명확화 질문을 합니다:**
- 이 시스템의 주요 사용자는 누구인가요?
- 달성해야 할 핵심 비즈니스 성과는 무엇인가요?
- 성공 지표는 무엇인가요?
- 규정 준수 또는 규제 제약이 있나요? (GDPR, HIPAA, PCI-DSS)
- 예상 규모는 어느 정도인가요? (사용자 수, 트랜잭션 수, 데이터 볼륨)
- 연동해야 할 기존 시스템이 있나요?
- 일정에 대한 기대치는 어떤가요?

저장 위치: `aidlc-docs/requirements/intent.md`

```markdown
# Intent: {제목}

## 비즈니스 목표
{달성해야 할 내용을 한 문단으로 기술}

## 주요 사용자
- {사용자 페르소나 1}: {설명 및 요구사항}
- {사용자 페르소나 2}: {설명 및 요구사항}

## 성공 지표
- {지표 1}: {목표값}
- {지표 2}: {목표값}

## 제약 조건
- {제약 조건 1}
- {제약 조건 2}

## 명확화 사항
- Q: {질문} → A: {이해관계자 답변}
```

### 2단계: 유저 스토리 생성

AI가 인수 조건이 포함된 표준 형식의 유저 스토리를 작성합니다. 각 스토리는 다음 기준을 충족해야 합니다:
- **독립적(Independent)** — 다른 스토리에 의존하지 않고 개발 가능
- **협상 가능(Negotiable)** — Construction 중 세부사항 조정 가능
- **가치 있는(Valuable)** — 사용자나 이해관계자에게 식별 가능한 가치 제공
- **추정 가능(Estimable)** — 노력을 대략적으로 평가할 수 있을 만큼 범위가 명확
- **작은(Small)** — 단일 Bolt 내에서 완료 가능
- **테스트 가능(Testable)** — 명확한 인수 조건 보유

**스토리 형식:**

```markdown
## US-{번호}: {제목}

**{사용자 페르소나}로서**
**{기능}을(를) 원합니다**
**{비즈니스 가치}을(를) 위해**

### 인수 조건
- [ ] {컨텍스트}일 때, {행동}하면, {기대 결과}
- [ ] {컨텍스트}일 때, {행동}하면, {기대 결과}

### 참고사항
- {추가 컨텍스트나 제약 조건}
```

### 3단계: Unit 구성

스토리를 Unit으로 그룹화합니다 — 독립적으로 구축 가능한, 응집된 느슨한 결합 블록입니다. DDD 원칙을 적용합니다:

- **Unit 내 높은 응집도** — 도메인 개념, 데이터, 비즈니스 규칙을 공유하는 스토리는 함께 묶음
- **Unit 간 느슨한 결합** — Unit 간 통신은 잘 정의된 인터페이스를 통해 이루어지며, 내부를 공유하지 않음
- **적절한 크기** — 각 Unit은 단일 개발자 또는 소규모 팀이 구축 가능해야 함

각 Unit별로 전용 파일을 생성: `aidlc-docs/story-artifacts/{unit-name}_stories.md`

```markdown
# Unit: {Unit 이름}

## 설명
{이 Unit이 제공하는 기능과 응집된 블록인 이유}

## 의존성
- 의존 대상: {다른 Unit, 있는 경우}
- 의존받는 대상: {다른 Unit, 있는 경우}

## 유저 스토리
{이 Unit에 속하는 모든 스토리 나열}
```

### 4단계: NFR 및 리스크 정의

전체 Unit에 공통으로 적용되거나 특정 Unit에 적용되는 비기능 요구사항과 리스크를 문서화합니다.

저장 위치: `aidlc-docs/requirements/nfr.md`

```markdown
# 비기능 요구사항

## 성능
- {NFR-P1}: {설명, 목표 지표}

## 보안
- {NFR-S1}: {설명}

## 확장성
- {NFR-SC1}: {설명}

## 가용성
- {NFR-A1}: {설명, SLA 목표}
```

저장 위치: `aidlc-docs/requirements/risks.md`

```markdown
# 리스크 관리 대장

| ID | 리스크 | 영향도 | 발생 가능성 | 완화 전략 |
|----|--------|--------|-------------|-----------|
| R1 | {설명} | 상/중/하 | 상/중/하 | {전략} |
```

### 5단계: PRFAQ 생성 (선택)

이해관계자가 보도자료 형식의 요약을 원하는 경우:

저장 위치: `aidlc-docs/requirements/prfaq.md`

```markdown
# PRFAQ: {제품/기능 이름}

## 보도자료
{2-3 문단: 무엇인지, 누가 혜택을 받는지, 핵심 기능}

## FAQ

### 고객 FAQ
Q: {질문}
A: {답변}

### 내부 FAQ
Q: {질문}
A: {답변}
```

### 6단계: Bolt 계획 수립

Unit을 어떤 순서로 실행할지 권장합니다 — 병렬, 순차, 또는 혼합 방식.

저장 위치: `aidlc-docs/plans/bolt_plan.md`

```markdown
# Bolt 실행 계획

## Bolt 1: {이름}
- **Unit:** {Unit 이름}
- **예상 소요 시간:** {시간/일}
- **의존성:** {먼저 완료되어야 하는 항목}
- **범위:** {특정 스토리 또는 작업}

## Bolt 2: {이름}
...
```

## 검증 체크포인트

각 단계 이후 산출물을 제시하고 다음과 같이 확인합니다:
- "{산출물}입니다. 확인 부탁드립니다. 수정이 필요한 부분이 있나요?"
- 명시적 승인 없이 다음 단계로 진행하지 않음
- 사용자가 변경을 요청하면 반영 후 다시 제시

## Inception 완료 기준

Inception 페이즈는 다음이 모두 충족되면 완료됩니다:
- [ ] Intent가 문서화되고 명확화됨
- [ ] 인수 조건이 포함된 유저 스토리 작성 완료
- [ ] 스토리가 Unit으로 그룹화됨
- [ ] NFR과 리스크가 문서화됨
- [ ] Bolt 계획이 수립됨
- [ ] 모든 산출물이 사용자의 승인을 받음
