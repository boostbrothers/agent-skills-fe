# Subtask 목록 생성 기준

Epic과 서비스명을 입력받아 Subtask 목록을 생성합니다.

## 입력

```
Epic 제목: [{{projectName}}] ...
서비스명: {{serviceName}}
```

## 실행 순서

```
1. Epic 제목에서 {{projectName}} 추출 (첫 번째 [] 안의 값)
2. Task 제목 생성: [{{projectName}}] {{serviceName}} 개발
3. Task 하위 기존 Subtask 목록 조회 (중복 방지)
   - 동일 제목의 Subtask가 이미 존재하면 → 스킵 대상으로 표시
   - 기존 Subtask가 있으면 사용자에게 목록을 안내
4. 작업 범위 파악 (우선순위: Task 디스크립션 > PROD 티켓 > Epic 디스크립션)
   - Task 디스크립션에 기술적 접근 방식이 있으면 이를 1차 소스로 활용
5. Subtask 목록 생성 전, Unit/E2E 테스트 포함 여부를 유저에게 질문
   → templates/subtask-list.md 의 질문 형식 참고
6. 유저 응답을 반영하여 필요한 Subtask 유형 선택
   - [화면]: 화면이 수반되는 작업 (기능 로직 포함 가능)
   - [기능]: 화면 없는 순수 로직 개선 시에만
   - [API 연동]: API 연동이 필요한 경우
   - [테스트] 시나리오 작성: 항상 포함
   - [테스트] Unit 테스트: 유저 응답에 따라 포함
   - [테스트] E2E 테스트: 유저 응답에 따라 포함
   - [문서]: 문서화가 필요한 경우에만
7. templates/subtask-list.md 형식으로 출력 (신규 항목과 스킵 항목 구분 표시)
8. 사용자 확인 후 Jira API로 신규 Subtask만 생성
```

> **참고**: Subtask 생성 시 담당자·기한은 상위 Task에서 자동 복사됩니다 (`references/automation-rules.md` 참조). Task의 담당자·기한이 미설정 상태에서 Subtask를 생성하면 빈 값이 복사되므로, Task에 담당자·기한을 먼저 설정한 후 Subtask를 생성하는 것을 권장합니다.

## 유형 선택 판단 기준

| 상황 | 등록할 유형 |
|------|-------------|
| 신규 화면 개발 | [화면] + [API 연동] + [테스트] |
| 기존 화면 기능 수정 | [화면] + [테스트] |
| 화면 없는 로직 개선 | [기능] + [테스트] |
| 문서화 필요 시 | + [문서] 추가 |
