# 티켓 계층 구조 및 제목 규칙

## 계층 구조

| 레벨 | 설명 |
|------|------|
| Initiative | 전사 프로젝트 · 연간/분기 목표 단위 |
| Epic | 과제의 최상위 묶음 단위 |
| Task | [{{projectName}}] {{serviceName}} 개발 · 서비스 단위로 생성 |
| Subtask | [화면] [기능] [API 연동] [테스트] [문서] 유형별 생성 |

---

## Task 제목 규칙

**형식:** `[{{projectName}}] {{serviceName}} 개발`

Task는 서비스 단위로 하나만 생성하며, 세부 작업은 Subtask로 분리합니다.

| 항목 | 설명 | 값 |
|------|------|----|
| `{{projectName}}` | 상위 Epic에서 자동 추출 | 예: `상담톡`, `예약개선`, `간편결제` |
| `{{serviceName}}` | Epic 또는 PROD 티켓에서 자동 판단, 불명확 시 사용자 선택 | `똑닥앱` / `병원어드민` / `PA` |

### {{serviceName}} 판단 순서

```
1. 상위 Epic 티켓 내용에서 서비스명 판단
2. 판단 불가 시 → Epic 하위 PROD 티켓 내용에서 서비스명 판단
3. 그래도 불명확한 경우 → 임의로 입력하지 않고 사용자에게 선택지 제공
```

작업 범위를 판단하기 어려운 경우 `references/service-names.md`의 사용자 선택지 형식으로 선택지를 제공합니다.

### Good ✅
- [상담톡] 똑닥앱 개발
- [예약개선] 병원어드민 개발
- [간편결제] PA 개발

### Bad ❌
- [상담톡] 채팅 화면 개발 → 세부 작업은 Subtask에 등록
- [상담톡] 똑닥앱/병원어드민 개발 → 서비스 혼용 (서비스별로 Task 분리)
- 똑닥앱 개발 → `{{projectName}}` 태그 누락

## Subtask 유형 및 등록 기준

Subtask는 아래 유형 중 **필요한 것만** 선택하여 등록합니다.
모든 유형을 필수로 등록할 필요는 없습니다.

| 유형 | 용도 | 등록 기준 |
|------|------|-----------|
| `[화면]` | UI 구현 + 관련 기능 포함 | 화면이 수반되는 작업이면 기능 로직도 함께 포함 가능 |
| `[기능]` | 비즈니스 로직 단독 처리 | 화면 없이 로직만 개선하는 경우에만 별도 등록 |
| `[API 연동]` | 백엔드 API 연결 및 데이터 바인딩 | Task 내 필요한 API 연동을 하나로 묶어 등록 |
| `[테스트]` | 시나리오 작성 / Unit / E2E | Task 완료의 필수 조건. 각각 분리 가능 |
| `[문서]` | 기능 명세, 가이드 등 산출물 | 문서화가 필요한 경우에만 등록 |

> `[화면]`에는 UI + 관련 기능 로직을 함께 작업할 수 있습니다.
> `[기능]`은 화면 없이 순수 비즈니스 로직만 수정하는 경우에 한해 별도 등록합니다.
