# Task 디스크립션 작성 기준

`references/classify-issue-type.md` 로 과제 유형을 판별한 후 아래 기준을 따릅니다.

## 공통: 중복 확인

> 이 섹션은 `SKILL.md` 실행 순서 2단계에서 참조됩니다.

모든 유형에서 디스크립션 작성 전, Epic 하위에 동일 제목의 Task가 이미 존재하는지 확인합니다.

```
1. Epic 하위 Task 목록 조회
2. 생성하려는 Task 제목과 동일한 티켓 존재 여부 확인
   - 존재하면 → "이미 {티켓번호} 티켓이 있습니다. 업데이트할까요?" 확인
   - 없으면 → 신규 생성 진행
```

### 업데이트 시 동작

기존 Task가 있어 "업데이트"를 선택한 경우:

1. 새로 생성한 디스크립션과 기존 디스크립션의 **변경 사항(diff)을 사용자에게 표시**
2. 사용자 확인 후 디스크립션 덮어쓰기
3. 기존 Subtask는 유지 (Subtask 재생성은 `references/generate-subtasks.md`의 중복 체크로 별도 처리)

### 취소 시 동작

사용자가 업데이트를 거부한 경우 → 기존 Task를 그대로 유지하고 스킬을 종료합니다.

---

## 운영과제인 경우

**BBROS 보드**의 Epic 티켓 **디스크립션**에 상세 기획 및 작업 내용이 포함되어 있습니다.
Epic 디스크립션을 기반으로 Task 디스크립션을 작성합니다.

```
1. BBROS 보드 Epic 티켓 디스크립션 조회
2. 배경/목적, 작업 범위, 영향 범위 추출
3. templates/task-description-ops.md 형식으로 작성
```

### 데이터 부족 시 대응

- Epic 디스크립션이 비어있거나 한 줄 이내인 경우 → 사용자에게 "Epic 디스크립션이 부족합니다. 작업 내용을 직접 입력해주세요." 안내

## 내부과제인 경우

**PE 보드**의 Epic 티켓 **디스크립션**에 상세 기획 및 작업 내용이 포함되어 있습니다.
Epic 디스크립션을 기반으로 Task 디스크립션을 작성합니다.

```
1. PE 보드 Epic 티켓 디스크립션 조회
2. 배경/목적, 작업 범위, 영향 범위 추출
3. templates/task-description-ops.md 형식으로 작성
```

### 데이터 부족 시 대응

- Epic 디스크립션이 비어있거나 한 줄 이내인 경우 → 사용자에게 "Epic 디스크립션이 부족합니다. 작업 내용을 직접 입력해주세요." 안내

## 중점과제인 경우

Epic 하위 Task 중 **PROD 보드(프로덕트팀 보드) 티켓** 존재 여부를 먼저 확인합니다.
PROD/Epic 정보를 분석하여 테크스팩 수준의 디스크립션을 자동 생성합니다.

```
1. Epic 하위 Task 목록 조회
2. PROD 보드 티켓(프로젝트 키 = PROD) 존재 여부 확인
   - 있으면 → PROD 티켓 내용 기반으로 분석
   - 없으면 → Epic 내용 기반으로 분석
3. 대상 프로젝트 코드베이스 탐색 (디렉토리 구조, 기존 컴포넌트/훅/스토어 파악)
4. 분석 결과를 바탕으로 기술적 접근 방식, 상태 관리, 영향 범위 등 테크스팩 섹션 자동 생성
5. templates/task-description-key.md 형식으로 작성
```

### 코드베이스 접근 불가 시 Fallback

대상 프로젝트 코드베이스에 접근할 수 없는 경우, 파일 경로 대신 컴포넌트/모듈명 수준으로 작성합니다.

```
## 기술적 접근 방식

### 신규 생성
1. ChatRoom 컴포넌트 — 채팅방 메시지 목록 화면
2. useChatMessages 훅 — 채팅 메시지 조회/전송

### 수정
1. AppNavigator — 상담톡 라우트 추가
```

### 데이터 부족 시 대응

- PROD 티켓 디스크립션이 비어있는 경우 → Epic 내용 기반으로 분석 (PROD 없는 경우와 동일 취급)
- Epic 디스크립션도 부족한 경우 → 사용자에게 "PROD/Epic 디스크립션이 부족합니다. 작업 내용을 직접 입력해주세요." 안내
