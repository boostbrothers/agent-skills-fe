# Subtask 목록 출력 템플릿

## 템플릿

```
Task: [{{projectName}}] {{serviceName}} 개발

Subtask:
- [화면] {화면명} UI 구현
- [API 연동] {기능명} 관련 API 연동
- [테스트] 시나리오 작성        ← 필수
- [문서] {기능명} 명세서 작성   ← 필요한 경우만
```

> `[테스트] 시나리오 작성`은 Task 완료의 필수 조건으로 항상 포함합니다.
> `[테스트] Unit 테스트`와 `[테스트] E2E 테스트`는 Subtask 목록 생성 전 아래 형식으로 유저에게 확인합니다.

## Unit / E2E 테스트 포함 여부 질문 형식

Subtask 목록을 생성하기 전, 아래 질문을 먼저 합니다:

```
테스트 Subtask 포함 여부를 선택해주세요.
시나리오 작성은 기본으로 포함됩니다.

1. Unit 테스트 포함
2. E2E 테스트 포함
3. Unit + E2E 테스트 모두 포함
4. 포함하지 않음
```

유저 응답에 따라 해당 항목을 Subtask 목록에 추가하여 출력합니다.

---

## 예시 1 — 신규 화면 개발, Unit + E2E 포함 ([상담톡] 똑닥앱 개발)

```
Task: [상담톡] 똑닥앱 개발

Subtask:
- [화면] 상담톡 진입 화면 UI 구현 (채널 목록, 미읽음 배지, 빈 상태)
- [화면] 채팅방 화면 UI 구현 (말풍선, 이미지 첨부, 날짜 구분선, 스크롤)
- [API 연동] 채팅 관련 API 연동 (목록 조회, 메시지 전송, 읽음 처리)
- [테스트] 시나리오 작성
- [테스트] Unit 테스트
- [테스트] E2E 테스트
- [문서] 상담톡 채팅 기능 명세서 작성
```

## 예시 2 — 기존 화면 수정, 테스트 미포함 ([예약개선] 똑닥앱 개발)

```
Task: [예약개선] 똑닥앱 개발

Subtask:
- [화면] 예약 상세 확인 화면 UI 구현 (병원명, 진료과, 예약 일시, 접수 상태)
- [화면] 예약 취소 확인 모달 구현 (취소 사유 선택, 환불 안내, 확인/취소 버튼)
- [API 연동] 예약 관련 API 연동 (예약 상세 조회, 예약 취소)
- [테스트] 시나리오 작성
```

## 예시 3 — 화면 없는 로직 개선, Unit만 포함

```
Task: [홈개선] 똑닥앱 개발

Subtask:
- [기능] 홈 화면 데이터 갱신 주기 로직 개선
- [테스트] 시나리오 작성
- [테스트] Unit 테스트
```

## 기존 Subtask가 있는 경우 (중복 방지 출력 형식)

`references/generate-subtasks.md` 3단계에서 기존 Subtask가 발견된 경우, 신규 항목과 스킵 항목을 구분하여 출력합니다.

```
Task: [상담톡] 똑닥앱 개발

기존 Subtask (스킵):
- ✓ [화면] 상담톡 진입 화면 UI 구현 — FE-101 (이미 존재)
- ✓ [API 연동] 채팅 관련 API 연동 — FE-102 (이미 존재)

신규 Subtask (생성 대상):
- [화면] 채팅방 화면 UI 구현 (말풍선, 이미지 첨부, 날짜 구분선, 스크롤)
- [테스트] 시나리오 작성
- [테스트] Unit 테스트
```

> 스킵 항목에는 기존 티켓 번호를 표시하여 사용자가 확인할 수 있도록 합니다.
> 신규 항목만 "이대로 Subtask를 생성할까요?" 확인 대상이 됩니다.

## 부분 실패 시 출력 형식

Subtask 생성 도중 API 에러가 발생한 경우, 성공/실패 항목을 구분하여 안내합니다.

```
생성 완료:
- ✓ [화면] 상담톡 진입 화면 UI 구현 — FE-201
- ✓ [화면] 채팅방 화면 UI 구현 — FE-202
- ✓ [API 연동] 채팅 관련 API 연동 — FE-203

생성 실패:
- ✗ [테스트] 시나리오 작성 — 생성 실패 (서버 오류)
- ✗ [테스트] Unit 테스트 — 미시도

실패한 2개 Subtask를 재시도할까요?
```

> 재시도 시 실패 항목만 대상으로 하며, 이미 생성된 항목은 건너뜁니다.
